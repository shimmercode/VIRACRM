## 3. Defects found by looking at the output

The automated checks passed long before the UI looked right. Each item below was caught
by reading a rendered PNG, then fixed, then pinned with a check.

### 3.1 The sidebar sat 118 px from the right edge

`.v-shell` had **no CSS rules at all** — the class existed in the Blade markup and
nowhere in the stylesheet, so the shell was a plain block and the sidebar stacked under
the content. Fixed by giving the shell a flex row; in RTL `row` already places the first
child on the right, so no `row-reverse` is needed.

### 3.2 The page scrolled sideways on phones (319 px of overflow)

`body.v-app` was `display: flex`. That made `.v-shell` a flex item, and a flex item's
default `min-width: auto` is its min-content width — which a table with `min-width:
560px` refuses to go below. The card grew to 637 px inside a 390 px viewport. Fixed by
making `.v-app` a block, and adding `min-width: 0` down the chain
`.v-content → .v-card → .v-card__body → .v-tablewrap`, with only the wrapper scrolling.

### 3.3 Stat cards stacked vertically instead of forming a grid

The markup emitted `.v-stats`, but the stylesheet only defined `.v-stats-grid`. Two
parallel class vocabularies had drifted apart. Fixed by defining `.v-stats`/`.v-stat`
(and `--warn`/`--danger`/`--compact` variants) against the classes the views actually use.

### 3.4 The sticky topbar clipped the page content

`.v-main` was not a scroll container, so `position: sticky` bound to the document and the
topbar painted over the heading. Fixed by making `.v-main` 100vh with `overflow: hidden`
and letting `.v-content` scroll, resetting all of it below 1023 px where the shell must
scroll as one page.

### 3.5 An unstyled blank page shipped in the tree

`resources/views/welcome.blade.php` was still the Laravel skeleton — Tailwind classes, no
product content. Deleted. A diff script (`tools/checks/unstyled.mjs`) now compares classes
used in Blade against classes defined in CSS; it initially reported 180, then 49 after the
skeleton was removed, now 0.

### 3.6 49 classes in Blade had no CSS at all

`v-taskgroup`, `v-list*`, `v-pagehead*`, `v-alert__*`, `v-card__{head,meta,link,foot}`,
`v-topbar__{start,end,searchicon}`, `v-profile*`, `v-menu__*`, `v-nav__divider`,
`v-navlink*`, `v-errorpage__*` and others rendered as unstyled text. All defined.

### 3.7 The mobile search field was 260 px tall

`.v-filterbar__search` declared `flex: 1 1 260px`. Below 480 px the bar flips to a
column, and a flex **basis** applies to the *height* on a column container — so the field
became 260 px tall. Fixed with `flex: 0 0 auto; width: 100%` inside the small-screen block.

### 3.8 Page titles were flush to the viewport edge

`--vira-space-7` and `--vira-space-9` were **never defined**. One undefined `var()`
invalidates the whole `padding` declaration, so `.v-content` had zero padding. Defining
the missing steps restored it — and `tools/checks/tokens.mjs` now fails on any undefined
reference.

### 3.9 Gregorian dates leaked into the UI (three separate times)

The dashboard task list showed `2026-11-16`; the customer detail panel showed
`تاریخ ثبت 2026-11-22`; the contracts table showed `start_date` as `2026-11-22`. All three
came from calling `->format('Y-m-d')` directly in Blade.

The fix is structural rather than a patch: a single `<x-fa-date>` component owns the
calendar decision, and both detail views plus the contract table now route through it. No
view calls `->format('Y-m-d')` any more. `tools/checks/calendar.mjs` renders the real pages
and fails on any ASCII date whose year exceeds 1600 — a year that can only be Gregorian.
The guard was validated by re-injecting the bug and confirming it fails.

### 3.10 The harness itself was lying

Two problems in the test tooling, both fixed:

- **Hard-coded record ids.** `/customers/1` and `/contracts/1` were screenshotted
  directly. After a re-seed those records no longer existed, the pages returned 404, and
  the shell assertions failed with `sidebar=null` instead of naming the real problem.
  Detail pages now resolve their id from the first row link on the corresponding list
  page, and `T-STATUS` asserts every page is below 400.
- **`T-TABLE-SCROLL` was unreachable on a 404.** A 404 page trivially passes "no
  horizontal overflow". The status check closes that hole.

Evidence screenshots were also showing rows left behind by test runs
(`شرکت آزمون Amwsa1duf`). Those records are now purged before capture.

## 4. Accepted limitations

- **Two controls under 28 px.** Both are inside dense table rows and are raised to a
  28 px minimum height by padding, but their intrinsic width stays smaller. Raising them
  further would force the customer table into more horizontal scrolling on a 390 px
  screen; the trade-off favours the table. WCAG 2.2 AA (24 px) is met.
- **`T-TYPE-MIN` reports 12 px.** The brief's floor is 11 px with 12 px preferred; the
  smallest rendered text is exactly 12 px.
- **Chromium is not vendored.** The sandbox cannot reach any package registry, so
  `tools/checks/ui-shots.mjs` and `calendar.mjs` locate the browser and `playwright-core`
  through `VIRA_CHROMIUM` / `VIRA_PLAYWRIGHT`, defaulting to the paths used in
  development. They exit 2 with a message rather than failing obscurely when absent.
- **Demo data is fictional by design.** Company names, `example.com` domains and phone
  numbers are obviously synthetic. The demo seeder is dev-only and is never invoked by
  `DatabaseSeeder`.

## 5. Reproducing this

```bash
# 1. runtime + data
PHP_WASM_PATH=/tmp/phpwasm/node_modules node docs/tools/php-cli.mjs tools/seed.php --demo
PHP_WASM_PATH=/tmp/phpwasm/node_modules node docs/tools/php-cli.mjs tools/checks/prepare.php

# 2. dev server
PHP_WASM_PATH=/tmp/phpwasm/node_modules node tools/dev-server.mjs --port 8080

# 3. assets (after any CSS/JS edit)
node tools/build-assets.mjs && node tools/build-js.mjs

# 4. gates
node tools/checks/css-audit.mjs && node tools/checks/contrast.mjs \
  && node tools/checks/unstyled.mjs && node tools/checks/tokens.mjs
node tools/checks/ui-shots.mjs
node tools/checks/calendar.mjs
```

`prepare.php` generates a random admin password and writes it to
`.arena/admin-password` (git-ignored, mode 0600); it creates `viewer1` with a
password that is never persisted. No fixed credential exists in the repository.
See `docs/phase-1/22-bootstrap-credential-policy.md`.

> **Superseded:** the browser suites no longer need this at all. Each one now
> clones the database and sets its own password inside its own copy, so they run
> with `node tools/checks/run-all.mjs` and no environment variables.

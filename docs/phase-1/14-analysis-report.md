## ۱. روش کار

1. **متن بریف ۳۲ بخشی به‌صورت خط‌به‌خط خوانده شد** (نه گزینشی).
2. هر جمله الزام‌آور به یک **الزام قابل تست مستقل** تبدیل شد (جمله‌های توصیفی/توضیحی جدا شدند).
3. هر الزام به: **گروه سند (۱۵ بخش) + ماژول + تست + اولویت + وزن + فاز** نگاشت شد.
4. تفکیک نوع:
   - `doc` = الزام صریح سند ۱۵ بخشی (بازگفته‌شده در بریف)
   - `brief` = الزام صریح بریف توسعه (معماری، امنیت، استقرار، مستندات)
   - `derived` = الزام مهندسی مشتق‌شده از الزام صریح (مثل RTM)
   - `proposed` = تصمیم پیشنهادی تیم که سند سکوت کرده یا «تکمیلی» اعلام شده؛ **نیازمند تأیید**
5. **هیچ الزامی حذف نشد**؛ مواردی که بریف به‌صورت اختیاری/پیشنهادی آورده، `proposed` ثبت شده‌اند.

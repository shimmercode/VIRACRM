## ۲. قرارداد کامپوننت‌های بحرانی (که امروز ساخته نشده‌اند)

### Secure Credential Reveal — سخت‌ترین قرارداد محصول

| # | تعهد | تست الزامی |
|---|------|-----------|
| S-۱ | رمز **هرگز** در HTML اولیه نیست | اسکن HTML صفحه با مقدار رمز → ۰ یافت |
| S-۲ | رمز **هرگز** در پاسخ فهرست API نیست | بررسی payload |
| S-۳ | Reveal با `POST` است، نه `GET` | بررسی متد Route |
| S-۴ | پاسخ `Cache-Control: no-store` | بررسی هدر |
| S-۵ | بدون مجوز → ۴۰۳ | تست با کاربر بدون مجوز |
| S-۶ | هر reveal → Audit (بدون مقدار) | بررسی ردیف `audit_logs` |
| S-۷ | خودکار مخفی پس از ۳۰s | تست زمان‌بندی |
| S-۸ | Re-auth پس از ۱۵ دقیقه | تست نشست کهنه |

## ۳. الگوی پیاده‌سازی (تعهد کد)

```blade
{{-- ساختار اجباری هر کامپوننت --}}
@props(['label' => null, 'id' => null])

<div class="v-x">
  {{-- اگر تعاملی: عنصر بومی (button/a), نه div کلیک‌پذیر --}}
  {{-- اگر آیکن تنها: aria-label --}}
  {{-- اگر وضعیت: role="status" --}}
  {{-- اگر خطا: role="alert" --}}
</div>
```

**ممنوع:**
- `<div onclick>` به‌جای `<button>`/`<a>`
- کلاس جدید بدون استایل در `components.css`
- رنگ hardcode (`#fff`) به‌جای توکن
- `!important` برای حل تداخل
- آیکن بدون `aria-hidden` یا `aria-label`

## ۵. قرارداد تست هر کامپوننت

هر کامپوننت جدید حداقل **۳ اَسِرشِن** می‌خواهد:

1. **وجود و ساختار** — کلاس/DOM درست
2. **یک رفتار واقعی** — مثلاً chip کلید خودش را حذف می‌کند
3. **یک تضمین دسترس‌پذیری** — `aria`/focus/کيبورد

و اگر امنیتی است (reveal, PDF)، **تست منفی** هم لازم است:
«بدون مجوز → ۴۰۳».

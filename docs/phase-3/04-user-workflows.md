# 04 — گردش‌کارهای کاربر (User Workflows)

**Vira CRM** · Gate A · ۲ آذر ۱۴۰۵

هر گردش‌کار با: **هدف** · **گام‌ها** · **نقاط شکست** · **حالت‌های خطا** · **مجوز**.

---

## WF-01 — ثبت مشتری و پیشگیری از تکرار

**هدف:** یک بار ثبت اطلاعات، استفادهٔ همیشگی.

```
[داشبورد] → «مشتریان» → [+ مشتری جدید]
        ↓
انتخاب نوع: حقیقی / حقوقی
        ↓
فرم پویا (فیلدها تغییر می‌کنند)
        ↓
[ذخیره]
        ↓
┌─ تشخیص تکرار ─────────────────────────────┐
│ search_key نرمال‌شده (نام+شناسه/موبایل)     │
│ اگر مشابه یافت شد → هشدار + لینک به پرونده  │
│ «آیا همین است؟» با دکمهٔ «رفتن به پرونده»  │
│ کاربر می‌تواند صریحاً «مشتری متفاوت است» بزند│
└────────────────────────────────────────────┘
        ↓
پروندهٔ مشتری (۳۶۰°)
```

**نقاط شکست (با پاسخ طرح):**

| شکست | پاسخ |
|------|------|
| کد ملی تکراری در دو رکورد | **هشدار**، نه خطای مطلق — سند می‌گوید «تا حد امکان» جلوگیری |
| کاربر آگاهانه تکرار می‌کند | مجاز، ولی Audit ثبت می‌شود |
| فرم نیمه‌پر رها می‌شود | draft؟ **تصمیم: خیر** — مشتری بدون نام ذخیره نمی‌شود |

**مجوز:** `customers.view` / `customers.create`

## WF-02 — قرارداد از قالب تا PDF نهایی

**هدف:** سند حقوقی امضاشدنی، با نسخهٔ تثبیت‌شده.

```
پروندهٔ مشتری → [+ قرارداد]
        ↓
انتخاب نوع قرارداد (طراحی/سئو/سایر)
        ↓
انتخاب قالب (فعال‌ها)
        ↓
جایگذاری خودکار placeholderها از مشتری
        ↓
ویرایشگر متن (پیش‌نویس)
        ↓
[پیش‌نمایش PDF] ← قبل از نهایی‌سازی
        ↓
┌── نهایی‌سازی ────────────────────────────────┐
│ ✔ مجوز contracts.finalize                     │
│ ✔ همهٔ placeholderها شناخته‌شده               │
│ ✔ مبلغ با حروف پر شده                         │
│ ✘ اگر ناقص → پیام صریح، نه نهایی              │
└──────────────────────────────────────────────┘
        ↓
snapshot در contract_versions + تولید PDF + contract_files
        ↓
وضعیت: draft → active
        ↓
[آیا قالب بعداً ویرایش شود؟] → PDF نهایی دست‌نخورده ✅
```

**قاعدهٔ تثبیت‌شده:** `contract_versions.content_html` منبع PDF است، **نه** قالب فعلی.

**تمدید:** قرارداد جدید با `renewed_from_id` → قبلی به `renewed` می‌رود، تاریخچه‌اش می‌ماند.

**مجوز:** `contracts.create/update/finalize`

## WF-03 — پروژهٔ سئو با دسترسی اجباری

**هدف:** پروژه فقط با دسترسی‌های کامل فعال شود.

```
[پروژه‌ها] → [+ پروژه] → نوع: سئو
        ↓
فرم سئو: دامنه، پکیج، مبلغ، تاریخ، کلمات کلیدی
        ↓
[ذخیره پیش‌نویس] → status = draft ✅ (ناقص هم ذخیره می‌شود)
        ↓
تب «دسترسی‌ها» → افزودن WordPress / Hosting / GSC / GA
        ↓
[نهایی‌سازی] ← تلاش
        ↓
┌── اعتبارسنجی دسترسی اجباری ─────────────────┐
│ credential_requirements برای «سئو»:          │
│   WordPress: الزامی?  ✔                      │
│   Hosting:   الزامی?  ✔                      │
│   ...                                        │
│ اگر هر اجباری غایب → ❌ ۴۲۲ + پیام:           │
│ «نهایی‌سازی ممکن نیست: رمز وردپرس ثبت نشده»  │
└──────────────────────────────────────────────┘
        ↓ (پس از تکمیل)
status = active
        ↓
[PDF عمومی]  ← بدون هیچ رمزی
[PDF محرمانه] ← مجوز جدا + هشدار + Audit
```

**نقطهٔ امنیتی حیاتی:** لیست دسترسی‌ها **همیشه ماسک** است. رمز فقط با کلیک
«نمایش» و درخواست سرور و پس از تأیید مجوز + Audit.

**مجوز:** `projects.*`, `credentials.view/manage/reveal/export`

## WF-04 — فاکتور و گزارش سئو (دو زنجیرهٔ مستقل)

**هدف:** یادآوری که دیر نمی‌شود، و مستقل بودن دو نوع.

```
پروژهٔ سئو → تب «فاکتورها» → [+ رویداد فاکتور]
                                 موعد: ۱۴۰۵/۰۹/۱۰
                                 مبلغ/شرح
        ↓
سیستم: یادآور در ۱۴۰۵/۰۹/۰۸ + روز موعد + عقب‌افتاده

پروژهٔ سئو → تب «گزارش‌ها» → [+ رویداد گزارش]
                                 موعد: ۱۴۰۵/۰۹/۱۰ (مستقل)
        ↓
سیستم: یادآور جدا برای گزارش
```

**سناریوی حیاتی — تکمیل فاکتور:**

```
مدیر فاکتور را فرستاد → [انجام شد] روی یادآور فاکتور
        ↓
✅ یادآور فاکتور بسته می‌شود
❌ یادآور گزارش **باز می‌ماند**  ← الزام سند §12
```

**سناریوی تغییر تاریخ:**

```
موعد از ۰۹/۱۰ به ۰۹/۱۵
        ↓
یادآور ۰۹/۰۸ حذف، یادآور ۰۹/۱۳ ساخته
        ↓
❌ هیچ یادآور تکراری ساخته نمی‌شود  ← unique_key
```

## WF-05 — دسترسی محرمانه و خروجی امن

**هدف:** رمز در دسترس مجاز، هرگز بدون ردیابی.

```
پروژه → تب «دسترسی‌ها»
        ↓
جدول: نوع | URL | username | رمز (••••••) | آخرین تغییر
        ↓
[👁 نمایش]  ← هر بار
        ↓
┌── چهار بررسی قبل از پاسخ ──────────────────┐
│ ۱. مجوز credentials.reveal                  │
│ ۲. Policy روی رکورد                         │
│ ۳. Re-auth اگر نشست > ۱۵ دقیقه (OD-26)     │
│ ۴. ثبت Audit (بدون مقدار)                   │
└─────────────────────────────────────────────┘
        ↓
رمز نمایش داده می‌شود → پس از ۳۰s خودکار مخفی
        ↓
[PDF محرمانه]
        ↓
مجوز credentials.export + Audit + واترمارک «محرمانه»
```

**خطاهای ممکن:**

| خطا | پاسخ |
|-----|------|
| بدون مجوز reveal | ۴۰۳ + Audit `denied` |
| نشست منقضی | redirect به login با بازگشت |
| کلید رمزنگاری خطا | پیام «رمز قابل بازیابی نیست» + ثبت خطا — **بدون نمایش ciphertext** |

## WF-06 — پرسنل و حقوق

**هدف:** فیش درست، تاریخچهٔ محفوظ.

```
[پرسنل] → [+ پرسنل] → نام، کد ملی، سمت، حقوق پایه
        ↓
[تخصیص پروژه] → انتخاب پروژه‌ها
        ↓
[حقوق] → [+ دوره] → ماه/سال شمسی
        ↓
[محاسبه] → پیش‌نمایش اقلام (پایه، پورسانت، پاداش، کسور، مساعده)
        ↓
┌── بازبینی ─────────────────────────────┐
│ مدیر اقلام را می‌بیند و می‌تواند تعدیل کند│
└────────────────────────────────────────┘
        ↓
[تأیید] → قفل دوره + snapshot
        ↓
PDF فیش (فارسی، امضا)
        ↓
❌ تغییر حقوق فعلی کارمند → فیش تأییدشده **تغییر نمی‌کند**
```

**وابسته به OD-16** (فرمول پورسانت).

## WF-07 — یادداشت و کار شخصی

```
داشبورد → کارتل → [+ یادداشت]
        یا
پروندهٔ مشتری/پروژه → [+ یادداشت]  ← به رکورد وصل می‌شود
        ↓
عنوان، شرح، موعد، اولویت
        ↓
در کارتل «امروز» یا «پیش‌رو»
        ↓
[انجام شد] → به تاریخچه می‌رود، **حذف نمی‌شود**
```

## WF-08 — گزارش و خروجی

```
[گزارش‌ها]
        ↓
تب/فیلتر: مالی | قرارداد | پروژه | پرسنل
        ↓
بازهٔ تاریخ شمسی + فیلتر
        ↓
جدول (همیشه) + نمودار (فقط اگر سؤال کسب‌وکار را جواب دهد)
        ↓
[خروجی PDF]
```

**قاعدهٔ سخت:** هر نمودار **باید** جایگزین جدولی داشته باشد (دسترسی‌پذیری + دقت).

## WF-09 — بازیابی رمز فراموش‌شده (عملیاتی)

**هیچ مسیر وب وجود ندارد — طراحی آگاهانه.**

```
مدیر رمز را فراموش کرد
        ↓
اپراتور با SSH:
  php artisan vira:reset-admin-password --generate
        ↓
رمز یک بار چاپ می‌شود (نه در history، نه در ps)
        ↓
ورود + تغییر اجباری رمز
```

**پیش‌نیاز عملیاتی:** دسترسی shell به هاست. اگر نباشد → بازیابی فقط از بکاپ دیتابیس.

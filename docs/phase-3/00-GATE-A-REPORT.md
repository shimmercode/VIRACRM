## D. مهندسی

### Backend — Modular Monolith، بدون تغییر معماری

```
app/{Models, Http/Controllers/<Domain>, Requests, Policies, Enums,
     Services/{Security,Reminders,Documents,Payroll,Contracts}, Support}
```

**افزوده نمی‌شود:** Repository، Event Sourcing، CQRS، Microservice، Livewire،
Tailwind. **حفظ می‌شود:** `permission:` روی هر Route، whitelist sort،
`search_key`، `expiring` مشتق، `Money` ریال.

### دیتابیس — **پایهٔ سالم، صفر migration تخریبی**

✅ FK با `constrained()` · ✅ رفتار حذف · ✅ unique constraint‌های درست ·
✅ index روی ستون‌های جستجو · ✅ `integer` ریال (نه float) · ✅ جداول snapshot نسخه

**حداکثر ۲ جدول جدید:** `contract_placeholders`, `backup_runs`.

**ناوبری تأییدشده:** رویداد فاکتور/گزارش در `work_items` است (۹ ردیف)، نه جدول جدا.

### امنیت — ۱۷ تهدید بررسی شد

**قوی:** AES-256-GCM · bcrypt · throttle · CSRF · whitelist SQL · Audit (۲۳۲ ردیف،
شامل ۲۷ `denied`) · رمز در لاگ نمی‌رود · reset وب عمداً نیست.

**ضعف:** لایهٔ سوم Policy غایب · ماژول دسترسی‌ها نیست · امنیت PDF پیاده نشده.

**ریسک بحرانی که باید کتباً تأیید کنید:** گم‌شدن `VIRA_CREDENTIAL_KEY` =
بازگشت‌ناپذیری همهٔ رمزهای دسترسی.

### Reminder Engine

منطق (۴۳ اَسِرشِن) + `unique_key` idempotent + `job_runs` observability
= **آماده، اما بدون Scheduler**. سه سناریو بر اساس H-15 طراحی شد.

### PDF — **بلوکه‌کنندهٔ شمارهٔ ۱**

هیچ موتور PDF نیست. **mPDF** پیشنهاد شد: تنها گزینه‌ای که Composer-نصب است و
bidi/shaping فارسی را بومی درست می‌دهد، بدون باینری/Node.

### فایل — ✅ درست

`local.root = storage_path('app/private')` — خارج از public. Vazirmatn TTF برای PDF موجود.

### سازگاری هاست — **۱۴ از ۲۱ مورد نامعلوم**

❌ PHP · ❌ extensions · ❌ MySQL · ❌ Composer · ❌ cron · ❌ memory · ❌ Document Root ·
❌ SSL · ❌ storage · ❌ backup · ❌ queue

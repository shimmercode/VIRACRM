# ADR-FILE-001 — معماری ماژول فایل: Hybrid با WebDAV مستقل

**وضعیت:** Proposed (نیازمند تأیید کارفرما) · **تاریخ:** ۲ آذر ۱۴۰۵ (2026-11-23) · **فاز:** F0
**مرتبط:** `FILE_STORAGE_ARCHITECTURE.md` · `WEBDAV_VPS_ARCHITECTURE.md` · `WEBDAV_CRM_AUTHORIZATION_BRIDGE.md`

---

## زمینه

VIRA CRM باید یک فضای کاری فایل سازمانی (Vira Drive) داشته باشد که:

- مالکیت سازمانی داشته باشد (نه شخصی)؛
- مجوزهایش از CRM بیاید و **مجوز ماژول‌های CRM را دور نزند**؛
- نسخه‌بندی، قفل و Audit واقعی داشته باشد؛
- از Windows File Explorer با WebDAV کار کند؛
- CRM روی cPanel بماند و بدتر نشود.

سه گزینه بررسی شد: **A) ساخت کامل**، **B) یکپارچه‌سازی محصول آماده**، **C) ترکیبی**.

## تصمیم

**گزینهٔ C (Hybrid) انتخاب می‌شود:**

| لایه | انتخاب | چرا |
|------|--------|-----|
| مدل داده، مجوز، نسخه، قفل، Audit، UI | **اختصاصی در CRM** (`app/Modules/Files`) | تنها راه «یک منبع حقیقت مجوز» |
| پروتکل WebDAV | **sabre/dav 4.7.x** روی **VPS مستقل** | کتابخانهٔ بالغ، BSD-3، قفل PDO، PHP خالص |
| بایت‌ها | **Object Storage سازگار S3** | مقیاس‌پذیر، مستقل از cPanel، قابل تعویض |
| Online Office | **F3** (خارج از دامنهٔ F1) | تصمیم قطعی کارفرما |

> **`sabre/dav` هیچ جدول مجوزی ندارد.** هر عملیات از CRM تأیید می‌گیرد و در صورت خطا **Fail-Closed** است.

## گزینه‌های رد‌شده

| گزینه | امتیاز وزن‌دار | دلیل رد |
|-------|:-------------:|---------|
| A — Build کامل | ۷.۶ | نوشتن سرور WebDAV از صفر = ریسک پذیرش پروتکل؛ کندترین مسیر |
| B — Nextcloud / ownCloud | ۴.۶ | **مدل مجوز موازی** با CRM (وزن ۲۰ شکست می‌خورد)؛ UI و برند بیرونی؛ بار عملیاتی روی cPanel |
| B′ — Seafile CE | — | قفل، Audit و مجوز ریزدانه در CE وجود ندارد (Pro-only) |
| MinIO به‌عنوان Storage | — | Community Edition بایگانی شده و نگهداری نمی‌شود |
| SMB عمومی | — | ممنوعیت صریح؛ خطر امنیتی؛ پروتکل متفاوت از WebDAV |
| WebDAV داخل Laravel روی cPanel | — | یک پردازهٔ PHP به ازای هر درخواست WebDAV، عدم کنترل BasicAuth/حجم، شکنندگی |

## پیامدها

### مثبت

- یک Resolver مجوز برای UI، API، دانلود و WebDAV.
- نسخه/قفل/Audit اختصاصی و قابل اثبات.
- UI کاملاً هم‌راستا با Design System و RTL واقعی.
- Storage قابل تعویض بدون تغییر منطق.
- آمادگی WOPI برای F3 بدون بازنویسی.

### منفی (پذیرفته‌شده)

| هزینه | کاهش |
|-------|------|
| یک VPS اضافه برای نگهداری | یک سرویس کوچک، مستند Runbook |
| یک درخواست شبکه در هر عملیات WebDAV | کش ۳۰ ثانیه‌ای + batch برای PROPFIND |
| مسئولیت سخت‌سازی sabre/dav روی ماست | Deployment + Threat Model |
| پیچیدگی دو سیستم | قرارداد صریح + Test Plan |

## ریسک‌های باقی‌مانده

| # | ریسک | پذیرش |
|---|------|-------|
| R1 | Windows WebClient Deprecated و سقف ۵۰MB/۴GB | **پذیرفته با مستندسازی صریح** |
| R2 | کارایی واقعی اندازه‌گیری نشده | F1 موظف به اندازه‌گیری |
| R3 | بدون اسکن بدافزار | OD-127 |

## نتیجه

این تصمیم **بر پایهٔ شواهد** گرفته شده، نه محبوبیت: تنها گزینه‌ای که هم مجوز یکپارچه می‌دهد، هم cPanel را نمی‌شکند، هم WebDAV استاندارد دارد.

**تأیید این ADR پیش‌نیاز شروع F1 است.**

# مستندات API

## این برنامه API عمومی ندارد

این را اول بخوانید، چون مهم‌ترین جملهٔ این سند است.

- **`routes/api.php` وجود ندارد.** تنها فایل‌های مسیر `routes/web.php`،
  `routes/review.php` و `routes/console.php` هستند.
- **هیچ بستهٔ احراز هویت API نصب نیست** — نه Sanctum، نه Passport، نه JWT
  (بررسی `composer.json`).
- **هیچ توکن، کلید API یا امضای درخواستی وجود ندارد.** احراز هویت فقط
  کوکی نشست است.
- از ۱۰۵ مسیر، **۰** مسیر با `api` در نام یا URI وجود دارد.

پس اگر دنبال «مستندات endpointهای REST» هستید: چیزی برای مستندکردن وجود ندارد.
نوشتن چنین سندی، مستندسازیِ یک API خیالی می‌شد.

## سطح HTTP واقعی

همهٔ ۱۰۵ مسیر، مسیرهای وب لاراول‌اند (تأییدشده با
`tools/checks/routes.php`):

| متد | تعداد |
|---|---|
| GET | 53 |
| POST | 32 |
| PUT | 10 |
| DELETE | 10 |
| **جمع** | **105** |

از این ۱۰۵ مسیر، ۱۰۱ تا احراز هویت‌شده‌اند و **همه** مجوز اعلام می‌کنند؛ ۷ استثنا
با دلیل در
[`SECURITY_ARCHITECTURE.md`](SECURITY_ARCHITECTURE.md) فهرست شده‌اند و
`tools/checks/route-permissions.php` آن را به‌عنوان یک gate بررسی می‌کند.

### قرارداد درخواست

| مورد | رفتار |
|---|---|
| احراز هویت | کوکی نشست (`config/session.php`: عمر ۱۲۰ دقیقه، `http_only`، `same_site=lax`) |
| CSRF | میدل‌ور `web` لاراول؛ هر فرم توکن دارد |
| مجوز | میدل‌ور `permission:<code>` روی مسیر |
| پاسخ | HTML (Blade)، با چیدمان RTL فارسی |
| خطا | 403/404/419/429/500/503 با صفحهٔ خطای خود برنامه، نه صفحهٔ پیش‌فرض Symfony |
| کش | `Cache-Control: no-store, no-cache, must-revalidate, private` |

### تنها پاسخ JSON

یک کنترلر JSON برمی‌گرداند: `CredentialController::reveal()`
(`app/Http/Controllers/Credentials/CredentialController.php:195`). این یک
endpoint عمومی نیست؛ یک فراخوانی داخلی از جاوااسکریپت صفحه است که رازِ
رمزنگاری‌شده را برای نمایش لحظه‌ای می‌گیرد. پشت `credentials.reveal` است، و هر
فراخوانی‌اش با `AuditRecorder::revealed()` ثبت می‌شود.

`tools/checks/credential-shots.mjs` اثبات می‌کند که راز در DOM رندرشده نیست —
یعنی این پاسخ تنها راه رسیدن به مقدار است و صفحه آن را از قبل لو نمی‌دهد.

## خروجی گرفتن از داده

به‌جای API، دو راه خروجی وجود دارد:

1. **PDF** — چهار خروجی (`app/Services/Pdf/`): قرارداد، پروژه، اعتبارنامه،
   فیش حقوقی. جزئیات در [`pdf/PDF_ENGINE.md`](pdf/PDF_ENGINE.md).
2. **گزارش‌ها** — صفحه‌های گزارش با `reports.export`.

## اگر واقعاً به API نیاز است

این یک تصمیم محصول است، نه یک کار باقی‌مانده. ساختن API یعنی افزودن:

- لایهٔ احراز هویت جدا از نشست (توکن + انقضا + ابطال)،
- نسخه‌بندی مسیرها،
- نرخ‌محدودسازی جدا از `throttle:10,1`ِ صفحهٔ ورود،
- پاسخ خطای ساخت‌یافتهٔ JSON به‌جای صفحهٔ HTML،
- و آزمون‌های اختصاصی خودش.

هیچ‌کدام از این‌ها امروز وجود ندارد.

## ۵. حفظ رگرسیون موجود — قاعدهٔ سخت

> **هیچ تستی ضعیف یا دور زده نمی‌شود تا تغییر جدید «قبول» شود.**

این قاعده در فاز ۲ نقض شده بود (تست Spinner) و اصلاح شد. در فاز ۳:

| قاعده | پیاده‌سازی |
|-------|-----------|
| افزودن سوییت جدید → `required: true` | همان الگوی `run-all.mjs` |
| هر سوییت مستقل (DB جدا) | `browser-flow.mjs` موجود |
| اجرا انحصاری | قفل اجرا (دستور §22.17) |
| Exit Code ملاک است | `runner-contract.mjs` |

### **قفل اجرا (الزام جدید دستور §22.17)**

امروز اگر دو نفر هم‌زمان `run-all.mjs` اجرا کنند، `.arena/flows/` تصادم می‌کند
(این را در فاز ۲-E عملاً دیدم). **باید اضافه شود:**

```js
// قفل سادهٔ فایل‌محور با PID
const lock = '.arena/run.lock';
if (fs.existsSync(lock)) { /* بررسی PID زنده → خروج با کد ۳ */ }
```

**این یک ضعف واقعی است که تا امروز فقط مستند شده بود، نه رفع.**

2. ✅ مجوز در middleware **و** Policy
3. ✅ FormRequest با پیام فارسی
4. ✅ حالت‌های empty/loading/error
5. ✅ واکنش‌گرا در ۷ عرض
6. ✅ کیبورد-دسترس + RTL
7. ✅ تست Feature
8. ✅ تست UI
9. ✅ Audit برای عملیات حساس
10. ✅ اسکرین‌شات در `evidence/`

**اگر یکی نباشد → `PARTIAL`، نه `DONE`.**

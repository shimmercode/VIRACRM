### یافتهٔ مهم: رگرسیون، بانک مشترک را تغییر می‌دهد — و مقصرش پیدا شد

`database/database.sqlite` **gitignore** است، پس `git status` هیچ تغییری نشان نمی‌دهد —
اما محتوایش عوض می‌شود. هش منطقی (هش همهٔ ردیف‌های همهٔ جدول‌ها، نه بایت‌های فایل):

| لحظه | ردیف‌ها | هش منطقی |
|---|---:|---|
| پیش از رگرسیون | ۵۱۰ | `29e2fcbf1c1bc5fcd8aeb5e185291694…` |
| پایان اجرای ۱ | ۵۱۰ | `41bc94d1e422c8a4c9d982954df3f2e1…` |
| پایان اجرای ۲ | ۵۱۰ | `71b8b7a980f44ac69c7e99037c538bc2…` |

تعداد ردیف‌ها در هر سه حالت **دقیقاً یکسان** است (۵۸ جدول / ۵۱۰ ردیف) — پس شمارش
ردیف‌ها تغییر را نشان نمی‌دهد؛ فقط مقایسهٔ محتوا نشان می‌دهد.

**مقصر، با bisect تک‌سوئیتی پیدا شد.** هر ۱۴ سوئیت اول یکی‌یکی اجرا شدند و هش
پیش و پس از هر کدام گرفته شد:

```
clean    unit / views / policies / route-permissions / route-smoke
clean    composer-integrity / query-performance / docs-integrity
clean    flow-login / flow-authed / flow-authz / flow-crud / customer-create
MUTATES  authorization   d2143d11 → 468ebd9b
```

**دقیقاً چه چیزی عوض می‌شود — یک ستون از یک ردیف:**

```
--- users: -1 +1
   WAS (2, 'کاربر مشاهده‌گر', 'viewer1', …, '$2y$12$1KdzIVhRKyzFIQqv…', …)
   NOW (2, 'کاربر مشاهده‌گر', 'viewer1', …, '$2y$12$nrD1WJi6OpT1KX7d…', …)
```

ستون ۵ جدول `users` = `password` (تأیید با `PRAGMA table_info(users)`).
`tools/checks/authz.php:23-32` این کار را می‌کند:

```php
$viewer = User::query()->firstOrNew(['username' => 'viewer1']);
$viewer->fill([ … 'password' => Hash::make($pw), … ]);
$viewer->save();
```

`Hash::make()` هر بار **salt تصادفی** تازه می‌زند، پس هر اجرای رگرسیون یک هش جدید
می‌نویسد — و این **دقیقاً** سه هش متفاوتِ بالا را توضیح می‌دهد (پایه + دو اجرا).
`updated_at` هم جابه‌جا می‌شود (`2026-11-27 13:24:58`).

**این خرابی داده نیست.** عمدی است: همان فایل می‌گوید رمز ثابت در فایل commit‌شده
نباید باشد. اما دو پیامد عملی دارد:

1. **`database/database.sqlite` یک artefact پایدار نیست** و نباید به عنوان «بانک
   اولیهٔ تمیز» مستقر شود. برای استقرار `migrate --seed` روی بانک خالی اجرا کنید.
2. **`viewer1` در این فایل رمزی دارد که هیچ‌کس نمی‌داند** — چون آخرین بار یک تست
   آن را نوشته. این خودش دلیل دیگری است که این فایل مستقر نشود.

**چه چیزی مقصر نیست** — هر سه با فرمان اثبات شدند:
- `php tests/run.php` → هش پیش و پس از اجرا **یکسان** (`6825b95b…` هر دو بار).
- `tools/checks/artisan-probe.php` و `scratch-count.php` → هر سه مسیر خطرناک را
  رد می‌کنند و با `exit 3` خارج می‌شوند.
- ۱۳ سوئیت دیگرِ بازهٔ ۱–۱۴ → هش دست‌نخورده.

**تصمیم: عمداً تغییرش ندادم.** اصلاحش (بازگرداندن هش اصلی پس از اجرا) اگر سوئیت

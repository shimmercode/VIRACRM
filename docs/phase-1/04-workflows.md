# VIRA CRM — گردش‌کارهای اصلی (فاز ۱)

> هر گردش‌کار: پیش‌شرط، گام‌ها، قواعد، وضعیت‌ها، خطاها و الزامات مرتبط.
> تاریخ همه موعدها روی **روز تقویمی Asia/Tehran** محاسبه می‌شود (REQ-12.08).

---

## W1 — ثبت مشتری و ضدتکرار (REQ-03)

```text
[فرم] انتخاب نوع (حقیقی/حقوقی)
   └─ حقیقی: نام، نام خانوادگی، کد ملی (۱۰ رقم، checksum)
   └─ حقوقی: نام شرکت، شناسه ملی (۱۱ رقم، همه ارقام)
        ↓
[اعتبارسنجی سمت سرور] FormRequest
        ↓
[تشخیص تکرار] سه کلید: national_id | digits(phone) | registrable_domain
   ├─ تطابق → هشدار «رکورد مشابه وجود دارد» + پیوند به پرونده موجود
   │            (ثبت فقط با تأیید صریح مدیر + ثبت در audit)
   └─ بدون تطابق → ذخیره
        ↓
[پرونده ۳۶۰°] نمایش قراردادها/پروژه‌ها/فاکتورها/گزارش‌ها/یادداشت‌ها/فایل‌ها
```

| خطا | رفتار |
|---|---|
| کد ملی نامعتبر | پیام فارسی دقیق، بدون ذخیره |
| کد ملی تکراری | هشدار با لینک پرونده موجود |
| دامنه بدون پروتکل | نرمال‌سازی خودکار (`https://`، حذف `www`) |

## W2 — قرارداد: قالب → متن → نسخه نهایی → PDF (REQ-04)

```text
انتخاب مشتری + نوع قرارداد + قالب
        ↓
[Placeholder Engine] جایگذاری اطلاعات مشتری/قرارداد
   {{customer.name}} {{customer.company}} {{customer.national_id}}
   {{customer.phone}} {{customer.address}} {{contract.amount}}
   {{contract.start_date}} {{contract.end_date}} {{project.type}}
        ↓
[پیش‌نمایش] (هیچ ذخیره‌ای انجام نمی‌شود)
        ↓
[ویرایش دستی متن] ← مجاز در وضعیت draft
        ↓
[ذخیره نسخه] contract_versions{body_snapshot, data_snapshot}
        ↓
[نهایی‌سازی] is_final=true · قفل ویرایش
        ↓
[PDF فارسی] موتور مرکزی → ذخیره فایل → قابل چاپ/دانلود مجاز
        ↓
[بارگذاری نسخه امضاشده] kind=signed (اختیاری، نسخه اصلی حفظ می‌شود)
```

قاعده کلیدی: `data_snapshot` نسخه نهایی را از تغییرات آینده مشتری مصون می‌کند (REQ-04.07).
تمدید: قرارداد جدید با `renewed_from_id` و وضعیت `renewed` برای قبلی (سابقه حفظ).

## W3 — پروژه سئو: پیش‌نویس → تکمیل دسترسی اجباری → نهایی (REQ-05, REQ-06)

```text
ایجاد پروژه (type=seo) → وضعیت draft
        ↓
تکمیل فیلدهای سئو + کلمات کلیدی (تعداد = COUNT واقعی)
        ↓
ثبت دسترسی‌ها برای هر credential_type با is_required_for_seo=1
        ↓
[تلاش نهایی‌سازی] SeoProjectFinalizer
   ├─ همه اجباری‌ها کامل → is_finalized=true
   └─ ناقص → 422 + فهرست موارد ناقص (با لینک مستقیم)
```

نمایش بصری: پروژه پیش‌نویس با Badge «پیش‌نویس ناقص» و شمارنده «۳ از ۵ دسترسی»؛
پروژه نهایی با Badge «فعال/نهایی».

## W4 — فاکتور دوره‌ای و یادآوری D-2 (REQ-12)

```text
تعریف دوره: period_key=1405-01، planned_send_date=1405/01/25 (میلادی ذخیره)
        ↓
Scheduler روزانه (cron هر دقیقه، Job روزانه 00:05 Tehran)
        ↓
برای هر دوره باز:
   fire_date = planned_send_date − 2 روز تقویمی
   upsert scheduled_events(unique_key=sha256(event_type|subject|period|fire_date))
        ↓
کارتابل:
   D-2 … D-1 → «امروز» (یادآوری پیش از موعد)
   D          → «امروز» + badge «سررسید»
   > D        → «عقب‌افتاده» (تا تعیین تکلیف باز می‌ماند)
        ↓
ثبت انجام: شماره فاکتور، مبلغ، تاریخ صدور، فایل، توضیح
        ↓
state=done → خروج از لیست باز، حفظ سابقه
```

**استقلال:** جدول `invoices` و `seo_reports` جدا، `event_type` جدا، `unique_key` جدا؛
انجام یکی هیچ اثری بر دیگری ندارد (REQ-12.05).
**تغییر تاریخ:** رکورد قبلی `dismissed` + `superseded_by`؛ رکورد جدید با `fire_date` جدید؛
سابقه تغییر در `audit_logs` و `scheduled_events.meta` (REQ-12.06).

## W5 — گزارش سئو (REQ-12.04)

همان W4 با `event_type=report_due`، `planned_report_date`، وضعیت‌های
`pending → prepared → sent` و D-2 مستقل. انجام گزارش هیچ اثری بر یادآوری فاکتور ندارد.

## W6 — مشاهده رمز و دریافت PDF محرمانه (REQ-06)

```text
درخواست مشاهده رمز
   → Policy credentials.reveal (Backend، نه UI)
   → (اختیاری) احراز مجدد رمز عبور اگر آخرین تأیید > ۱۵ دقیقه
   → decrypt (AES-256-GCM، AAD=credential:{id})
   → Audit: credential.revealed {user, credential_id, project_id, ip}
   → پاسخ با Cache-Control: no-store، بدون لاگ مقدار
        ↓
درخواست PDF محرمانه
   → Policy credentials.pdf + احراز مجدد
   → تولید PDF در حافظه (جدا از PDF عمومی)
   → فایل موقت با توکن HMAC کوتاه‌عمر (≤۲ دقیقه، یک‌بارمصرف)
   → Audit: credential.pdf.downloaded
   → حذف فایل موقت پس از دانلود/انقضا
```

## W7 — پرونده پرسنل و حقوق (REQ-07)

```text
پرونده پرسنل (اطلاعات هویتی، سمت، تاریخ شروع، حقوق پایه، فایل قرارداد)
        ↓
تخصیص پروژه‌ها → تعداد پروژه فعال هر کارشناس
        ↓
باز کردن دوره حقوق (سال/ماه شمسی) → محاسبه با قواعد مؤثر از تاریخ
        ↓
Draft فیش → بازبینی مدیر → نهایی‌سازی (Final)
        ↓
اصلاحیه فقط با نسخه جدید + دلیل + Audit (سابقه حفظ)
        ↓
PDF فیش (فارسی، RTL، محل امضای پرسنل و مدیر)
```

**فرمول دقیق نیازمند تأیید است (Q-08).** موتور، پارامتری است؛ هیچ فرمولی اختراع نمی‌شود.

## W8 — یادداشت و کارتابل (REQ-08, REQ-02)

```text
ثبت یادداشت (عنوان، شرح، سررسید، اولویت، اتصال به مشتری/قرارداد/پروژه)
        ↓
Scheduler روزانه → scheduled_events(event_type=note_due)
        ↓
کارتابل: امروز | آینده | عقب‌افتاده | انجام‌شده
        ↓
علامت انجام → state=done + حفظ سابقه
```

## W9 — جستجو و گزارش (REQ-09)

```text
جستجوی سراسری: نرمال‌سازی فارسی (ی/ك، ZWNJ، ارقام فارسی) → LIKE ایندکس‌شده / FULLTEXT
   مشتری: نام، تلفن، کد/شناسه ملی، دامنه
   قرارداد: مشتری، نوع، وضعیت، تاریخ، مبلغ
   پروژه: نوع، مسئول، وضعیت، مشتری، تاریخ
        ↓
گزارش‌ها (قرارداد فعال/منقضی/نزدیک انقضا، فاکتور/گزارش موعددار/عقب‌افتاده، پرسنل)
        ↓
خروجی PDF (الزامی) · XLSX (تکمیلی، با کنترل دسترسی + Audit)
```

## W10 — Backup / Restore (REQ-15.02)

```text
backup: database (mysqldump) + storage خصوصی + .env (رمزنگاری‌شده)
      → آرشیو خارج از web root + نگهداری N نسخه + چک‌سام
      → ثبت job_runs
restore: روی محیط تمیز → migrate → import → تست ورود + بررسی نمونه داده
      → گزارش تست بازیابی (T-BKP-02)
```

# سازگاری هاست — VIRA CRM

**وضعیت کلی: `BLOCKED`** — دسترسی به هاست واقعی وجود ندارد.

> **هیچ‌کدام از موارد زیر `PASS` نیست.** ۱۴ از ۲۱ بررسی نمی‌تواند اجرا شود.
> ادعای «روی هاست کار می‌کند» بدون این‌ها **بی‌پایه** است.

## ۳. PDF — تصمیم معلق

**mPDF** تنها موتور قابل نصب با Composer است که bidi بومی دارد.

| مورد | وضعیت |
|------|-------|
| نصب محلی | `NOT TESTED` (Composer نیست) |
| فارسی/RTL در PDF | `NOT TESTED` |
| روی هاست | **`BLOCKED`** |
| فونت فارسی | **`BLOCKED`** — فونت رسمی موجود نیست |

> **تأیید مشروط کارفرما:** mPDF فقط مشروط تأیید شده. تست محلی کافی **نیست**.
> تا اجرای واقعی روی هاست، وضعیت `BLOCKED` می‌ماند.

## ۴. ریسک‌های خاص هاست اشتراکی

| ریسک | اثر | کاهش |
|------|-----|------|
| `exec` غیرفعال | بکاپ/CLI نمی‌کارند | جایگزین PHP-native |
| Cron محدود | یادآوری تأخیر | fallback after-response |
| `flock` نبودن | قفل تست | `O_EXCL` استفاده شد ✓ |
| محدودیت memory | PDF بزرگ fail | صفحه‌بندی دسته‌ای |
| `mod_rewrite` | مسیرها | تست `.htaccess` |
| SSL | کوکی `Secure` | الزامی |

## ۵. لوگو — `BLOCKED`

لوگوی رسمی وی‌را **موجود نیست**. جایگزین موقت استفاده می‌شود.
**تا دریافت، هرگونه ادعای «برندینگ کامل» نادرست است.**

---

## ۶. چه چیزی برای رفع لازم است

1. دسترسی SSH یا cPanel به ساب‌دامین
2. اجرای `tools/checks/host-probe.php` روی هاست
3. خروجی `php -m`, `php -i`, `mysql --version`
4. تست واقعی cron
5. فونت فارسی + لوگوی رسمی

**بدون این‌ها، این سند `BLOCKED` می‌ماند — و بی‌صداقتی است اگر غیر این بنویسم.**

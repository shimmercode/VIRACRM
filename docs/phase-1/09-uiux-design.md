# VIRA CRM — طرح UI/UX (فاز ۱)

> این سند طرح است، نه محصول. هیچ صفحه‌ای ساخته/اجرا نشده؛ نمونه بصری در فاز ۲ (پس از تأیید)
> تحویل می‌شود. الزامات: REQ-11.01 .. REQ-11.05.

## ۱. اصول

1. **فارسی RTL واقعی** — `<html dir="rtl" lang="fa">`، نه صرفاً `text-align: right`.
2. **Desktop First + Responsive** — نقاط شکست 1280 / 1024 / 768 / 480.
3. **خلوت و اولویت‌دار** — هر صفحه یک هدف؛ داشبورد بدون شلوغی.
4. **فرم کوتاه، مرحله‌ای در صورت نیاز** — تب/استپر برای مشتری، قرارداد، پروژه.
5. **وضعیت‌ها همیشه واضح** — Badge با رنگ + متن، نه فقط رنگ.
6. **دسترس‌پذیری** — فوکوس واضح، کنتراست ≥ 4.5:1، برچسب فرم، ناوبری کیبورد.

## ۷. حالات (States)

| حالت | نمایش |
|---|---|
| Loading | Skeleton یا اسپینر در دکمه با `aria-busy` |
| Empty | تصویر/آیکن سبک + متن راهنما + دکمه اقدام |
| Error | پیام فارسی قابل فهم + «تلاش مجدد»؛ جزئیات فنی فقط در لاگ |
| Success | Toast کوتاه + بازگشت به لیست |
| Validation | پیام زیر فیلد + فوکوس روی اولین خطا |

### ۷.۱ حالات به‌ازای هر صفحه (چه چیزی کاربر می‌بیند)

| صفحه | Empty (هیچ داده) | Loading | Error |
|---|---|---|---|
| داشبورد | «هنوز داده‌ای نیست» + دکمه «افزودن مشتری» | ۴ کارت skeleton | «دریافت آمار ناموفق بود» + تلاش مجدد |
| لیست مشتریان | «مشتری‌ای ثبت نشده» + دکمه «مشتری جدید» | ۸ سطر skeleton | پیام + نگه‌داشتن فیلترها |
| جستجو | «نتیجه‌ای پیدا نشد» + پیشنهاد اصلاح عبارت | اسپینر کوچک در فیلد | «جستجو ناموفق بود» |
| پرونده مشتری | (بی‌معنا — همیشه داده دارد) | skeleton تب فعال | خطای همان تب، نه کل صفحه |
| پروژه | «اطلاعات تکمیل نشده» + دکمه «تکمیل» | skeleton تب | خطای همان تب |
| دسترسی‌ها | «برای این پروژه دسترسی ثبت نشده» + «افزودن» | skeleton جدول | «دریافت دسترسی‌ها ناموفق» — **نه نمایش رمز** |
| کارتابل | «کاری برای امروز نیست 🎉» | skeleton ۵ کارت | پیام + تلاش مجدد |
| حقوق | «دوره‌ای محاسبه نشده» + «محاسبه دوره» | skeleton جدول | «محاسبه ناموفق» + جزئیات در لاگ |
| گزارش‌ها | «داده‌ای برای این بازه نیست» + تغییر بازه | skeleton نمودار | جایگزین نمودار با پیام |
| تنظیمات | (بی‌معنا) | skeleton فرم | خطای اعتبارسنجی per field |

**قواعد سخت:**
- **هیچ صفحه‌ای هرگز فقط «سفید» نمی‌ماند.** یکی از سه حالت بالا همیشه نمایش داده می‌شود.
- در حالت Error، **هیچ جزئیات فنی** (مسیر فایل، SQL، نام جدول) به کاربر نشان داده نمی‌شود؛
  فقط یک کد پیگیری کوتاه که در لاگ قابل جستجو است.
- در حالت Loading، دکمه‌های اقدام غیرفعال و `aria-busy="true"` می‌شوند.
- Empty state همیشه **یک اقدام بعدی** پیشنهاد می‌دهد (نه فقط پیام).

## ۸. تاریخ شمسی (REQ-11.04)

- DatePicker شمسی با تقویم داخلی (بدون وابستگی CDN).
- ورود: `۱۴۰۵/۰۱/۲۵` یا `1405-01-25`؛ ذخیره: `DATE` میلادی.
- نمایش همه‌جا شمسی + در PDF.
- تبدیل دوسویه با تست (T-DATE-01..03)؛ **مبنای نوروز باید تأیید شود (Q-06)**.

## ۹. RTL و دسترس‌پذیری

- استفاده از logical properties؛ هیچ `float:left` دستی.
- اعداد: فارسی در متن، لاتین در جدول‌های مالی/کدها برای خوانایی.
- هدف لمسی حداقل ۴۴px در موبایل؛ جدول‌ها در موبایل کارت‌محور.
- `aria-live` برای Toast؛ `focus-visible` برای همه کنترل‌ها.

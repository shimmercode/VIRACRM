# FILE_WORKSPACE_ADR_EVIDENCE — بازبینی شواهد ADR-FILE-001

**نسخه:** 1.0 · **تاریخ:** ۲ آذر ۱۴۰۵ (2026-11-23) · **فاز:** Decision Closure
**موضوع:** ADR-FILE-001 (`Proposed`) — هر مؤلفه در کدام سطح شواهد است؟
**دسته‌های شاهد:** `PROVEN` · `DESIGN-ONLY` · `NEEDS PoC`

> **قاعدهٔ سخت:** «طراحی شده» شاهد نیست. `PROVEN` فقط وقتی صادر می‌شود که
> **(۱)** کد در همین مخزن اجرا شده، یا **(۲)** مستند رسمی نسخهٔ مشخص تأیید کرده باشد.
> هر ادعایی که فقط در سند طراحی آمده، `DESIGN-ONLY` است. هر ادعایی که به رفتار ویندوز، VPS یا
> شبکهٔ واقعی وابسته است، `NEEDS PoC` است — **حتی اگر طراحی‌اش کامل باشد**.

---

## ۰. خلاصهٔ اجرایی

| سطح شاهد | تعداد | معنا |
|----------|------:|------|
| `PROVEN` | **۴** | اجرا شده در همین مخزن یا مستند رسمی قطعی |
| `DESIGN-ONLY` | **۵** | طراحی کامل، صفر اجرا |
| `NEEDS PoC` | **۲** + ۶ زیرآیتم | بدون آزمون واقعی، ادعا بی‌معناست |

> **حکم کلی:** ADR-FILE-001 در وضعیت `Proposed` **باقی می‌ماند**. هیچ مؤلفه‌ای از سطح
> `NEEDS PoC` بدون آزمون واقعی به `PROVEN` ارتقا نمی‌یابد.

## ۲. تفصیل هر مؤلفه

### ۲.۱. sabre/dav 4.7.1 — `PROVEN`

| پرسش | پاسخ | منبع / تاریخ |
|------|------|---------------|
| نسخه | **4.7.1**، انتشار ۲۰۲۶-۰۷-۰۷ | `api.github.com/repos/sabre-io/dav` · ۲۰۲۶-۱۱-۲۳ |
| نگهداری | فعال — آخرین push ۲۰۲۶-۱۱-۰۱ | همان |
| مجوز | **BSD-3-Clause** — سازگار با محصول اختصاصی | همان |
| RFC 4918 (WebDAV) | **Supported** | `sabre.io/dav/standards-support/` |
| RFC 3253 (Versioning) | **not planned** | همان |
| قفل | `Locks\Backend\PDO` + `Locks\Plugin` — **opt-in** | `sabre.io/dav/locks/` |
| PHP | خالص، بدون Node.js | همان |

**چه چیزی اثبات نشده:** نصب واقعی، کارکرد پشت nginx با TLS، و رفتار با WebClient ویندوز.
**حکم:** انتخاب کتابخانه **درست** است؛ استقرارش `NEEDS PoC`.

### ۲.۲. WebDAV روی VPS مستقل — `NEEDS PoC`

| جنبه | وضعیت |
|------|-------|
| طراحی | کامل (`WEBDAV_VPS_ARCHITECTURE.md`) |
| VPS واقعی | **هیچ** — اجاره نشده (منع خرید در فاز Decision Closure) |
| TLS واقعی | هیچ |
| آزمون بار | هیچ |
| نصب sabre/dav | هیچ |

**حداقل PoC لازم:** یک VPS موقت، nginx + PHP-FPM + sabre/dav، گواهی Let's Encrypt،
`PROPFIND`/`GET`/`PUT`/`LOCK` با `curl`، سپس Map Drive از ویندوز.
**دستور خرید VPS صادر نمی‌شود تا تصمیم OD-119 تأیید شود.**

### ۲.۳. Storage سازگار S3 — `DESIGN-ONLY`

| ادعا | واقعیت |
|------|--------|
| «بایت‌ها روی S3 می‌روند» | `league/flysystem-aws-s3-v3` **نصب نشده** |
| «SeaweedFS کار می‌کند» | هیچ نصب و آزمونی انجام نشده |
| «MinIO گزینه است» | **رد شد** — بایگانی (روش پژوهشی §۲.۵) |

**اجرا شده:** فقط `local` با `serve => true` (رفتار واقعی: بدون Range، Content-Type از محتوا).
**فاصله:** از «local اجرا شد» تا «S3 مقیاس‌پذیر» یک PoC کامل فاصله است.

### ۲.۴. CRM به‌عنوان مرجع مجوز — `PROVEN` (به‌صورت عمومی) / `DESIGN-ONLY` (برای فایل)

| شاهد | مقدار واقعی |
|------|-------------|
| جدول `permissions` | **۳۹** مجوز |
| جدول `roles` | **۴** نقش |
| جدول `role_permissions` | **۵۴** انتساب |
| اعمال سمت سرور | `EnsurePermission` روی **۲۱** مسیر |
| رد دسترسی Audit | `AuditRecorder::denied()` در همان middleware |
| Policy سطح رکورد | `ContractPolicy`, `ProjectPolicy` |

**آنچه اثبات شده:** «CRM می‌تواند مرجع مجوز باشد» — این **الگو کار می‌کند**.
**آنچه اثبات نشده:** اعمال همین الگو برای `file_nodes` با وراثت پوشه، Deny-wins و WebDAV.
**نتیجه:** پایه `PROVEN`؛ منطق `decide()` فایل `DESIGN-ONLY`.

### ۲.۵. پل احراز (authorization bridge) — `DESIGN-ONLY`

| مسیر طراحی‌شده | وجود دارد؟ |
|----------------|:----------:|
| `POST /api/dav/verify` | ❌ |
| `POST /api/dav/authorize` | ❌ |
| `POST /api/dav/authorize-batch` (≤۳۰۰ گره) | ❌ |
| `POST /api/dav/commit` | ❌ |
| `POST /api/dav/event` | ❌ |
| HMAC | ❌ |
| mTLS | ❌ |

**اما:** رانش واقعی `temporaryUrl()` و اعتبارسنجی امضا در همین مخزن **آزموده شد**
(۲۰۰ معتبر / ۳۰۲ با امضای بد) — یعنی «امضاشده» در Laravel کار می‌کند، ولی **این پل نیست**.

### ۲.۶. Fail-Closed — `DESIGN-ONLY`

| حالت | طراحی | کد |
|------|-------|:--:|
| CRM در دسترس نیست | رد | ❌ |
| توکن نامعتبر/منقضی | رد | ❌ |
| توکن ابطال‌شده | رد | ❌ |
| کاربر غیرفعال | رد | ❌ |
| `is_active=false` در CRM | `hasPermission()` → false (**موجود، `PROVEN`**) | ✅ |

**آخرین ردیف تنها بخش اثبات‌شده است.** رفتار شبکه‌ای Fail-Closed (timeout، خطای ۵۰۰، DNS) کد ندارد.

### ۲.۷. Locking — `PROVEN` در کتابخانه، `NEEDS PoC` در پروتکل

| لایه | سطح | شاهد |
|------|:---:|------|
| وجود قفل در sabre/dav | **`PROVEN`** | `Locks\Backend\PDO` + `Plugin` |
| قفل opt-in بودن | **`PROVEN`** | صفحهٔ Locks — بدون پلاگین، قفل وجود ندارد |
| davfs / Finder بدون قفل = read-only | **`PROVEN`** | همان صفحه |
| یکپارچگی با `file_locks` CRM | `DESIGN-ONLY` | OD-113 |
| قفل واقعی با WebClient ویندوز | **`NEEDS PoC`** | `SupportLocking=1` ولی آزمون نشده |

> **ریسک اصلی:** WebClient ویندوز رفتار قفل خودش را دارد. تا آزمون W-series،
> «قفل کار می‌کند» یک **ادعا** است، نه یافته.

### ۲.۸. Versioning — `DESIGN-ONLY`

| ادعا | واقعیت |
|------|--------|
| نسخه‌ها در CRM | `file_versions` insert-only — **طراحی** |
| بازیابی = نسخهٔ جدید | طراحی (`source='restore'`) |
| sabre/dav نسخه‌دهی می‌کند | **نه** — RFC 3253 در sabre **not planned** |

**این محدودیت مهم است:** نسخه‌سازی **باید** در CRM باشد، چون کتابخانه انجامش نمی‌دهد.
این تصمیم درست است، ولی **اجرا نشده**.

### ۲.۹. Audit — `PROVEN` عمومی، `DESIGN-ONLY` برای فایل

| شاهد | مقدار |
|------|-------|
| `audit_logs` در DB | **۲۳۲** ردیف واقعی |
| `AuditRecorder::denied()` | داخل `EnsurePermission` — **کار می‌کند** |
| رویدادهای فایل (`file.download` و…) | **تعریف‌نشده** |

### ۲.۱۰. Backup — `DESIGN-ONLY`

| جزء | وضعیت |
|-----|-------|
| RPO/RTO | پیشنهاد (OD-131) — تأییدنشده |
| بکاپ DB | طراحی (mysqldump روزانه) |
| بکاپ Storage | طراحی (نسخه‌بندی + کپی) |
| بکاپ L3 خارج از سایت | طراحی (OD-133) |
| اجرای واقعی | **هیچ** |

### ۲.۱۱. Restore — `DESIGN-ONLY` — **بالاترین ریسک**

| جنبه | وضعیت |
|------|-------|
| Runbook | مکتوب |
| تمرین بازیابی | **هرگز** |

> **قاعده:** «بکاپ تست‌نشده = بکاپ ناموجود». تا تمرین بازیابی انجام نشود،
> **هیچ ادعای بازیابی‌پذیری** مجاز نیست. این تنها مؤلفه‌ای است که شکافش می‌تواند
> در فاجعه، داده را برای همیشه از بین ببرد.

| # | PoC | چه چیزی را ثابت می‌کند | هزینه | بلوکه‌شده با |
|:-:|-----|------------------------|-------|--------------|
| P1 | نصب sabre/dav + nginx + TLS روی VPS | مؤلفهٔ ۲ | VPS موقت | OD-119 |
| P2 | پل احراز HMAC + mTLS | مؤلفهٔ ۵، ۶ | کد + VPS | OD-121, OD-122 |

| P5 | انتقال نزدیک **۴ GiB** روی ویندوز | سقف OD-116/117 | ویندوز + دیسک | OD-120 |

## ۴. اثر بر وضعیت ADR

| پرسش | پاسخ |
|------|------|
| آیا ADR-FILE-001 `Accepted` می‌شود؟ | **خیر.** `Proposed` باقی می‌ماند. |
| چرا؟ | ۵ مؤلفه `DESIGN-ONLY` و ۲ مؤلفه `NEEDS PoC` — طراحی کامل، اجرا صفر. |

| آیا انتخاب Hybrid (OD-101) در خطر است؟ | **خیر.** شواهد کتابخانه‌ای (sabre 4.7.1، مجوز، RFC) محکم است. |

## ۱. هدف این سند

دستور جدید، VIRA CRM را از «CRM مشتری/قرارداد/پروژه» به **سیستم عامل کسب‌وکار** آژانس دیجیتال ویرا ارتقا می‌دهد. دامنهٔ کار از ۹۶ نیازمندی قبلی به بیش از ۲۵۰ نیازمندی می‌رسد و ۱۸ ماژول جدید اضافه می‌شود.

این سند سه کار می‌کند:

1. **وضعیت واقعی امروز** را بدون خوش‌بینی ثبت می‌کند (فاز ۰).
2. **ترتیب اجرا** را تعیین می‌کند و وابستگی‌ها را صریح می‌کند.
3. **تعریف «تمام‌شده»** را برای هر ماژول می‌نویسد، تا «صفحه ساخته شد» با «قابلیت کار می‌کند» اشتباه نشود.

## ۳. قواعد اجرا (غیرقابل مذاکره)

این قواعد از دستور کارفرما استخراج شده‌اند و در همهٔ فازها اعمال می‌شوند:

1. **UI-only ممنوع.** هر دکمه، فرم، نمودار، فیلتر، جست‌وجو و منو باید عملکرد واقعی داشته باشد.
2. **هر ماژول = بک‌اند + UI + مجوز + Audit + تست.** اگر یکی نباشد، ماژول «تمام‌شده» نیست.
3. **هیچ داده یا فرمول ساختگی.** اگر داده نیست، «در دسترس نیست» نمایش داده می‌شود، نه صفر.
4. **تست روی دیتابیس جداگانه.** هرگز روی دیتابیس مشترک یا تولیدی.
5. **skipped هرگز passed گزارش نمی‌شود.**
6. **تصمیم باز = BLOCKED.** سؤال دقیق + گزینه‌ها ثبت می‌شود، کار مستقل ادامه می‌یابد.
7. **بدون Node در تولید، بدون Redis اجباری، بدون میکروسرویس، بدون WordPress.**

## ۴. تعریف «تمام‌شده» برای هر ماژول

یک ماژول وقتی «تمام‌شده» است که **هر هفت** مورد زیر را داشته باشد:

- [ ] Migration + مدل + رابطه‌ها
- [ ] Controller + FormRequest با اعتبارسنجی واقعی
- [ ] مسیرها با `permission:` روی همهٔ متدها
- [ ] مجوزهای جدید در `PermissionCatalog` **و** اعطا به نقش‌ها
- [ ] ثبت در `AuditRecorder` برای ایجاد/ویرایش/حذف/عملیات حساس
- [ ] تست Feature (assert واقعی روی وضعیت دیتابیس)
- [ ] تست جریان HTTP + اسکرین‌شات در ۷ عرض

## ۵. فازها و ترتیب اجرا

ترتیب بر اساس **وابستگی داده** است، نه جذابیت. حسابداری زودتر از BI می‌آید چون BI بدون داده مالی چیزی برای نشان دادن ندارد.

| فاز | محتوا | مقدمات | وضعیت |
|---|---|---|---|
| **۰** | حسابرسی، تثبیت، رفع نقص‌های باز | — | در جریان |
| **۱** | کارتابل کامل، یادداشت/وظیفه، پرسنل، تنظیمات، کاربران/نقش‌ها | فاز ۰ | کارتابل + یادداشت **انجام شد** |
| **۲** | حسابداری داخلی (پس از تأیید OD-41)، فاکتور، PDF | تأیید OD-41 | منتظر تصمیم |
| **۳** | فایل/ورک‌اسپیس سازمانی، پیوست‌ها | فاز ۱ | — |
| **۴** | فروش، مشتری ۳۶۰، تمدید، پیشنهاد، قرارداد | فاز ۲ | — |
| **۵** | هلدسک، QA، CSAT، جلسات، OKR، دانش | فاز ۴ | — |
| **۶** | منابع، BI، گردش‌کار، تأمین‌کننده، دارایی، پورتال | فاز ۲–۵ | — |
| **۷** | Vira Intelligence | همهٔ فازهای قبل | — |

### چرا این ترتیب

- **OD-41 مسدودکنندهٔ فاز ۲ است.** بدون تأیید نمودار حساب‌ها، هیچ منطق حسابداری نوشته نمی‌شود. کار مستقل (فاز ۱، ۳) ادامه می‌یابد.
- **BI بعد از حسابداری.** «سود خالص» بدون دفتر کل قابل محاسبه نیست. نشان دادن عدد ساختگی، نقض مستقیم قاعدهٔ ۳ است.
- **Vira Intelligence آخر.** هوش مصنوعی روی سرویس‌های واقعی کار می‌کند؛ تا وقتی سرویس‌ها وجود ندارند، ابزارهای AI چیزی برای صدا زدن ندارند.

## ۸. گزارش فاز ۰ (خلاصه)

**انجام شد:**
- حسابرسی کامل: چه کار می‌کند، چه جدول‌فقط است، چه نیست.
- رفع دو نقص واقعی: کارتابل قابل بستن نبود (DEF-01)، یادداشت بدون UI بود (DEF-02).
- کشف و رفع نقص سوم در همان مسیر: تاریخ جلالی نامعتبر بی‌صدا NULL می‌شد (DEF-03).
- ۴۳ مجوز (۸ مجوز جدید)، اعطا به ۴ نقش.
- تست: ۹ سوئیت / ۴۴۶ assert، جریان HTTP ۱۳/۱۳، اسکرین‌شات ۲۸/۲۸.

**جزئی:**
- تنظیمات، کاربران/نقش‌ها، پرسنل: هنوز UI ندارند (فاز ۱).

**مسدود:**
- OD-41 (نمودار حساب‌ها) — کل فاز ۲.

**قدم بعدی:**
1. ادامهٔ فاز ۱: کاربران/نقش‌ها، تنظیمات.
2. ارسال پیشنهاد نمودار حساب‌ها برای تأیید کارفرما (OD-41).

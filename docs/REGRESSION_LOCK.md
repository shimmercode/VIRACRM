# قفل رگرسیون — Regression Lock

**هدف:** تضمین مکانیکی اینکه کارِ تأییدشدهٔ گذشته نمی‌شکند.

---

## ۱. مکانیزم

```
node tools/checks/run-all.mjs --repeat 2
```

| خروجی | معنا |
|-------|------|
| ۰ | ۲۲ سوییت، همه سبز، تکرارپذیر، DB دست‌نخورده |
| ۱ | شکست واقعی |
| ۲ | ناتمام (`--fast`) |
| ۳ | اجرای هم‌زمان دیگر |

---

## ۲. آنچه قفل می‌شود

| مورد | اَسِرشِن | چرا |
|------|---------|-----|
| ورود/خروج | ۸ | دروازهٔ همه چیز |
| دسترسی پس از ورود | ۲۰ | جلسه و UI |
| رد دسترسی | ۱۱ | RBAC |
| CRUD مشتری/قرارداد | ۱۸ | جریان اصلی کسب‌وکار |
| کامپایل Blade | ۳۰ | هیچ view شکسته |
| کنتراست | همه | دسترس‌پذیری |
| نظم توکن | ۴۲ | عدم پراکندگی CSS |
| ۷ عرض × ۴ صفحه | ۲۱۸ | واکنش‌گرایی |
| جدول → کارت | ۲۱ | موبایل |
| ۷ صفحه × ۷ عرض | ۲۰۶ | چیدمان |
| اجزای DS | ۲۱ | یکپارچگی طراحی |
| قرارداد exit code | ۱۱ | خود runner |
| **قفل و همزمانی** | **۱۵** | **جدید** |

---

## ۳. قاعدهٔ تغییر

> **هیچ تغییری که اَسِرشِن موجود را ضعیف کند پذیرفته نیست.**

اگر تغییری تستی را می‌شکند، دو حالت:

1. **تغییر باگ است** → تغییر برگردد
2. **تست قدیمی شده** → فقط با **اثبات نوشتاری** که رفتار قدیم اشتباه بود

**بدون استثنا.**

---

## ۴. شواهد آخرین اجرا

| سنجه | مقدار |
|-------|-------|
| سوییت‌ها | ۲۲ |
| عرض‌های تست‌شده | ۷ (۳۹۰…۱۴۴۰) |
| تکرار | ۲ پاس |
| جداسازی | اندازه‌گیری هر پاس |
| قفل | اثبات‌شده با SIGKILL |

**جزئیات هر اجرا در `.arena/repeat-<stamp>.json`.**

## ۲. طراحی پیشنهادی (M8)

### ۲.۱ محتوا

| جزء | روش |
|-----|-----|
| دیتابیس | `mysqldump --single-transaction` |
| فایل‌های آپلود | آرشیو tar (بدون `vendor`, `node_modules`) |
| تنظیمات | `.env` **جدا** و رمزنگاری‌شده |
| اعتبارنامه‌ها | **از قبل رمزنگاری‌شده** — کلید جدا |

### ۲.۲ قواعد

| قاعده | دلیل |
|-------|------|
| بکاپ **بیرون** `public/` | جلوگیری از دانلود |
| رمزنگاری با کلید مجزا | نشت فایل = نشت داده |
| `--single-transaction` | عدم قفل جدول |
| بررسی یکپارچگی (checksum) | بکاپ خراب بدتر از بی‌بکاپ |
| نگهداری ۳۰/۱۵/۷/۳ (OD-35) | تعادل فضا/بازیابی |
| **تست بازیابی** ماهانه | بکاپ تست‌نشده = فرض |

### ۲.۳ جدول `backup_runs`

```
id · started_at · finished_at · status · size_bytes
checksum · path · triggered_by · error
```

## ۳. رویهٔ بازیابی (پیشنهادی)

```
۱. تأیید هویت اپراتور (دو نفر برای داده مالی)
۲. حالت تعمیر — سایت آفلاین
۳. بکاپ از وضعیت فعلی (حتی خراب)
۴. بازیابی DB
۵. بازیابی فایل‌ها
۶. اجرای Regression Suite کامل
۷. تأیید تراز حسابداری (اگر فعال)
۸. بازگرداندن آنلاین
```

**مرحلهٔ ۶ غیرقابل حذف است** — بازیابی بدون تست، ریسک است.

---

## ۴. ریسک فعلی

> **بدون بکاپ، یک خطای اپراتور = از دست رفتن همهٔ داده.**

این بالاترین ریسک عملیاتی پروژه است و در M8 باید رفع شود.
تا آن زمان، **هیچ ادعای آمادگی تولید وجود ندارد**.

---

## ۵. آنچه برای شروع لازم است

1. تصمیم: بکاپ روی همان هاست یا مقصد خارجی (OD)
2. فضای دیسک کافی
3. دسترسی `mysqldump` (SSH یا cron)
4. کلید رمزنگاری بکاپ
5. **مقصد خارج از هاست** — بکاپ هم‌مکان با داده، بکاپ نیست
